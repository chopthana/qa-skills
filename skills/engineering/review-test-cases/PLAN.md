# แผน: skill `review-test-cases`

สถานะ: **แผน ยังไม่ได้สร้าง skill** — เขียน 12 พ.ย. 2569 เพื่อสร้างวันที่ 13 พ.ย. 2569

## ปัญหาที่จะแก้

การรีวิว test case ชุดใหญ่ (ALC-2520 มี 63 เคส) ในแชตมีสามปัญหา

1. ส่งได้ทีละ 10 ข้อ ต้องเลื่อนขึ้นลงหา ไม่รู้ว่ารีวิวถึงไหนแล้ว
2. คำที่ซ้ำกันทุกเคส (precondition ของกระดานมาตรฐาน) ทำให้ตารางยาวจนอ่านไม่ออก พอย่อคำก็ไม่ตรงกับไฟล์จริง — **รีวิวของจริงต้องเห็นคำเต็มเหมือนในไฟล์**
3. เอาแชตไปรีวิวกับ BA / PO ไม่ได้ ต้อง screenshot หรือส่งไฟล์ Excel ให้เปิดเอง

## สิ่งที่ skill นี้จะทำ

เรียกครั้งเดียว → ได้หน้าเว็บส่วนตัว (ลิงก์แชร์ได้) ที่แสดงเคสทั้งชุดในฟอร์แมต 4 คอลัมน์เดียวกับที่ตกลงกันไว้
พร้อมช่องรีวิวทีละเคส → กดส่งกลับ → ผมแก้ไฟล์ .xlsx ต้นทางให้ แล้ว publish หน้าเดิมซ้ำให้เห็นว่าแก้อะไรไปแล้ว

## 2. หน้าเว็บ (Artifact)

ใช้ **Artifact** (หน้า HTML private บน claude.ai) ไม่ใช่ไฟล์ HTML ในเครื่อง เพราะไฟล์ในเครื่องทำสามอย่างนี้ไม่ได้

| ต้องการ | ไฟล์ในเครื่อง | Artifact |
|:--|:--|:--|
| ส่งลิงก์ให้ BA / PO เปิดดู | ❌ ต้องส่งไฟล์ | ✅ ลิงก์ |
| เก็บผลรีวิวค้างไว้ ปิดแล้วเปิดใหม่ยังอยู่ | ❌ | ✅ `db` capability |
| ผมอ่านผลรีวิวกลับได้ | ❌ copy-paste | ✅ `ArtifactData` |
| comment ที่เด้งเข้า session | ❌ | ✅ `ArtifactComments` |

### หัวตาราง — 4 คอลัมน์ + 1 คอลัมน์รีวิว

| # | หัวข้อ | Precondition + Step | Expected | รีวิว |
|:--|:--|:--|:--|:--|

**กฎเหล็ก: ห้ามย่อคำ** ทุกเซลล์ลอกจาก .xlsx มาตรง ๆ รวมการขึ้นบรรทัดใน cell
ไม่มี `[กระดานมาตรฐาน]` ไม่มี `…` ไม่ตัดท้าย ไม่รวบคำซ้ำ
(ใช้ `white-space: pre-wrap` ให้ `\n` ในเซลล์ขึ้นบรรทัดจริง)

### สองโหมด

หน้าเปิดมาเป็น **โหมดนำเสนอ** เสมอ — ตาราง 4 คอลัมน์ล้วน ไม่มีปุ่ม ไม่มีช่องพิมพ์
เอาไปกางรีวิวกับ BA / PO ได้ทันที คนที่ได้ลิงก์ไปดูจะเห็นแบบนี้

QA กดสวิตช์ **โหมดรีวิว** ที่แถบบน → คอลัมน์รีวิวโผล่ขึ้นมา
(จำสถานะสวิตช์ไว้ใน `localStorage` ต่อเครื่อง ไม่กระทบคนอื่น)

### สิ่งที่มีในคอลัมน์รีวิว แถวละชุด (เห็นเฉพาะโหมดรีวิว)

- สถานะ 3 ปุ่ม: **ผ่าน** / **แก้** / **ถาม BA** (เลือกได้หนึ่งอัน กดซ้ำเพื่อยกเลิก)
  — **ถาม BA** เป็นสถานะชั่วคราวสำหรับคุยในห้อง ไม่เขียนลงไฟล์
- ช่องพิมพ์ (textarea) "แก้เป็นอะไร / คำถามถึง BA" — เปิดเมื่อเลือก แก้ หรือ ถาม BA
- ชื่อผู้รีวิว — ดึงจาก `identity` capability ไม่ต้องพิมพ์
- เวลาที่รีวิวล่าสุด

### แถบบนสุด

- ชื่อการ์ด (จากชื่อไฟล์) + จำนวนเคสทั้งหมด
- ความคืบหน้า `รีวิวแล้ว 23 / 63` + แท่งเปอร์เซ็นต์
- ตัวกรอง: ทั้งหมด / ยังไม่รีวิว / ผ่าน / แก้ / ถาม BA / แก้แล้ว
- ช่องค้นหาข้อความในเคส
- ปุ่ม **ส่งกลับเพื่อแก้ไข**

### ปุ่ม ส่งกลับเพื่อแก้ไข ทำอะไร

1. ปิดชุดรีวิวรอบนั้น (stamp `batch` + เวลา + ชื่อคน) ลง db
2. แสดงสรุป: ผ่าน n ข้อ · แก้ n ข้อ · ถาม BA n ข้อ
3. แสดงคำสั่งหนึ่งบรรทัดให้ copy ไปวางใน Claude Code

**ข้อจำกัดที่ต้องรู้**: หน้าเว็บ **ปลุก session ของ Claude Code เองไม่ได้**
ดังนั้น "ส่งกลับ" = เก็บลง db ให้เรียบร้อย แล้วคุณวางคำสั่งหนึ่งบรรทัดมาหนึ่งที
ทางเดียวที่ push เข้ามาเองได้คือ **comment บน artifact** ซึ่ง session ที่ publish หน้านั้นอยู่จะได้รับ — ใช้เป็นช่องทางสำรองสำหรับ BA / PO ที่ขอแค่ comment

## 4. โหมด `--apply` — เอาผลรีวิวมาแก้ไฟล์

ลำดับงาน

1. อ่าน db (`collection: cases`) + comment ที่ยังไม่ตอบ
2. สำรองไฟล์เดิมก่อนแตะ → `<ชื่อไฟล์>.before-review-<batch>.xlsx` ใน scratchpad
3. แก้ทีละเคสตามสถานะ — **มีแต่ แก้ ที่แตะไฟล์**
   - **ผ่าน** → ไม่แตะเซลล์ แค่บันทึกว่ารีวิวแล้ว
   - **แก้** → แก้เซลล์ที่ระบุ (หัวข้อ / steps / expected / หมายเหตุ) ตามที่พิมพ์มา
   - **ถาม BA** → ไม่แตะไฟล์เลย คงสถานะไว้ใน db ให้ไปคุยต่อ แล้วค่อยเปลี่ยนเป็น ผ่าน / แก้
4. เขียนทับไฟล์เดิมที่ path เดิม
5. publish หน้าเดิมซ้ำ (url เดิม) — แถวที่แก้แล้วขึ้น ✔ แก้แล้ว + แสดง **ของเดิม / ของใหม่** ให้เทียบ
6. รายงานในแชต: เคสไหนแก้อะไร คำถามใหม่มีอะไร

### การแก้ไฟล์ — แก้เซลล์ในที่ ไม่ regenerate

ALC-2520 รอบนี้แก้ผ่าน `gen.py` ที่เขียนขึ้นเฉพาะการ์ดนั้น — **ใช้วิธีนั้นไม่ได้กับ skill**
เพราะการ์ดอื่นไม่มี `gen.py`

ดังนั้น `apply_review.py` ต้อง **แก้เซลล์ใน .xlsx โดยตรงด้วย openpyxl** เพื่อ
- ใช้ได้กับ workbook ของทีมทุกไฟล์
- รักษา format เดิม (สี เส้น ฟอนต์ data validation สูตรคอลัมน์ ลำดับ)

## 5. กฎเหล็ก (ยกมาจากข้อตกลงที่คุยกันไว้แล้ว)

1. **ห้ามย่อคำในหน้าเว็บ** แสดงเต็มเหมือนในไฟล์ทุกตัวอักษร
2. **ห้ามลบเคสที่มีอยู่เดิม** — "แก้" คือเขียนทับเนื้อหา ไม่ใช่ลบแถว
   เคสที่ลบได้คือเคสที่ skill/AI เพิ่มเข้าไปเองเท่านั้น และต้องถามก่อนลบทุกครั้ง พร้อมบอกว่าเคสนั้นมาจากไหน
3. **สำรองก่อนเขียนทับทุกครั้ง**
4. **หนึ่งเคส = หนึ่ง Pass/Fail** ถ้ารีวิวสั่งแก้จนเคสหนึ่งต้องตอบสองผล ให้แยกเป็นสองเคส (เลขใหม่ต่อท้ายชุด) แล้วรายงาน
5. **ไม่แตะโค้ดของแอป** skill นี้อ่านโค้ดได้ แก้ได้แต่ test case
6. **ไม่เงียบ** ข้อที่แก้ไม่ได้ / ขัดกับ spec ต้องรายงาน ไม่ใช่ปล่อยให้ดูเหมือนแก้แล้ว
7. **Precondition คงรูปแบบทีม** — `(Precondition …)` วงเล็บบรรทัดแรก เว้นบรรทัด แล้วค่อยขั้นตอนที่ 1 (ตามกฎที่ `spec-prototype-to-testcases` และ `testcase-coverage-audit` ถือไว้แล้ว)

## 7. ข้อตกลง (ตอบแล้ว 13 พ.ย. 2569)

1. **กดส่งกลับแล้วแก้เลย** ไม่ต้องเสนอรายการให้ยืนยันก่อน — แต่ยังสำรองไฟล์ก่อนแตะ และรายงานหลังแก้เสมอ
2. **BA / PO ดูเฉย ๆ** คนพิมพ์แก้คือ QA เอง
   ⇒ หน้าเว็บเปิดมาเป็น **โหมดนำเสนอ (read-only)** ตารางสะอาด ไม่มีปุ่ม เอาไปกางในห้องประชุมได้เลย
   มีสวิตช์ **โหมดรีวิว** ที่ QA กดเปิดเพื่อให้ปุ่มกับช่องพิมพ์โผล่
3. **หนึ่งหน้าต่อหนึ่งการ์ด** — รวมทั้ง sprint ไว้หน้าเดียวเป็น optional ไว้ทีหลัง (`--sprint <folder>` ยังไม่สร้างรอบนี้)
4. **สถานะ ถาม BA ไม่เขียนลงไฟล์** ไม่ต้องใส่ `⚠️ TBC Qn`
   เป็นสถานะชั่วคราวระหว่างรีวิว พอคุยกับ BA จบก็เปลี่ยนเป็น ผ่าน หรือ แก้ แล้ว resolve ไปในตัว
   ⇒ **มีแต่สถานะ แก้ ที่แตะไฟล์** สถานะ ผ่าน กับ ถาม BA ไม่แก้เซลล์ใดเลย
